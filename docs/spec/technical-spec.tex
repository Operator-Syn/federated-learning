% Technical specification for the inclusion-aware federated learning system.
%
% This document is NOT the thesis paper. It is the reference that the paper cites:
% numbered definitions, metric formulas, tunable parameters and conformance
% requirements. Build it standalone with `make`, or hand the PDF to the City Health
% Office as the technical annex to a data-sharing agreement.
%
% The paper includes the same sections from sections/ so the two documents cannot
% drift apart. Never restate a definition in the paper — cite its section number.
%
% The shared section files need a small preamble contract from the host document:
%   \core          the filled-square marker for entities the first build implements
%   L{..}          ragged-right paragraph column
%   spectab{..}    the table environment (grid, header fill, zebra) defined below
%   colours rule, headcell, rowshade
% A host that provides those four things can \input any section unchanged.

\newcommand{\open}[1]{\textcolor{red}{\textbf{[OPEN:} #1\textcolor{red}{\textbf{]}}}}
% Marker for entities the first build implements. A raised solid square rather than a
% footnote mark: those read as references to a note, and this marks a
% property of the row itself. Sized in ex so it tracks the surrounding type.
\newcommand{\core}{\kern0.22em\raisebox{0.3ex}{\rule{0.8ex}{0.8ex}}}
\newcolumntype{L}[1]{>{\raggedright\arraybackslash}p{#1}}

% Label/value row for the title page. A table was wrong here: putting \raggedleft
% in a p-column opens a paragraph and drops the label one line below its value.
% A hanging indent keeps both on one baseline and still aligns wrapped lines.
\newcommand{\metarow}[2]{%
  \par\noindent\hangindent=\dimexpr 2.35cm + 0.85em\relax\hangafter=1
  \makebox[2.35cm][r]{\color{muted}\scshape #1}\hspace{0.85em}#2\par}

% One table style for the whole document. Every section supplies only its column spec and
% the zebra rows; the chrome lives here, so it cannot drift table to table. A host document
% that \inputs sections/ must define this environment as well as \core and L.
\newenvironment{spectab}[1]{%
  \renewcommand{\arraystretch}{1.3}%
  \setlength{\arrayrulewidth}{0.4pt}%
  \arrayrulecolor{rule}%
  \begin{longtable}{#1}}%
 {\end{longtable}}

{\scshape\color{muted}\footnotesize Abstract}\par
\vspace{0.35em}
\begin{minipage}{\dimexpr\textwidth-1.4cm\relax}
{\linespread{1.06}\selectfont\small
This specification fixes the names the system uses: its entities, its selection
policy families, the formulas behind its metrics, and the parameters a deployment
may change. The thesis, the prototype and any City Health Office documentation are meant to
describe the same objects in the same words. It is a working document, not a
result. Definitions remain provisional until the review of related literature and
consultation with the City Health Office resolve the open decisions listed in
Section~\ref{sec:open}. A filled square marks the entities the first build implements;
the rest are defined for possible later implementation, subject to the open decisions in
Section~\ref{sec:open}.\par}
\end{minipage}
